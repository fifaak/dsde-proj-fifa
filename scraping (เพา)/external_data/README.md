# ข้อมูลเสริมสำหรับ Bangkok CCTV

ชุดนี้ใช้ `camera_id` จาก `cctv_info.csv` และช่วงวันที่ 25–31 สิงหาคม 2569 จากชื่อไฟล์ใน `cctv_images.zip` สคริปต์อ่านรายชื่อไฟล์ใน ZIP ได้โดยตรง จึงรันได้โดยไม่ต้องแตกไฟล์ภาพ

| ไฟล์ | แต่ละแถว | แหล่งข้อมูล |
| --- | --- | --- |
| `data/cameras.csv` | กล้องหนึ่งตัวพร้อมพิกัดและถนนใกล้เคียง | พิกัดและคำบรรยายจากชุดกล้องของวิชา ชื่อและแนวถนนจาก [OpenStreetMap ผ่าน BBBike](https://download.bbbike.org/osm/bbbike/Bangkok/) |
| `data/rain_hourly.csv` | กล้องหนึ่งตัวต่อหนึ่งชั่วโมง | [Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api) แบบ ECMWF IFS |
| `data/truck_rules.csv` | เงื่อนไขหนึ่งรายการต่อพื้นที่หรือเส้นทางและช่วงเวลา | [สนข. หัวข้อ 4.1.2](https://www.otp.go.th/uploads/tiny_uploads/PDF/2569-03/20260319_5_mot08081_planon_2569_Truck.pdf#page=30) และ [ราชกิจจานุเบกษา เล่ม 142 ตอนพิเศษ 31 ง](https://ratchakitcha.soc.go.th/documents/58726.pdf) |

## รันซ้ำ

ใช้ Python 3.12 ขึ้นไปใน virtual environment แยกได้ รันจากโฟลเดอร์โปรเจกต์ที่มี `cctv_info.csv` และ `cctv_images.zip`

```sh
python3 -m venv .venv-scraping
source .venv-scraping/bin/activate
python -m pip install -r "scraping (เพา)/external_data/requirements.txt"
python -B "scraping (เพา)/external_data/collect.py" all
```

เลือก `cameras`, `rain` หรือ `rules` แทน `all` เพื่อสร้างทีละไฟล์ ใช้ `--metadata`, `--images` และ `--output` เพื่อระบุตำแหน่งไฟล์และโฟลเดอร์ผลลัพธ์ หากแตกไฟล์ภาพไว้ใน `data/cctv_images/` แล้ว หรือมีแค่ไฟล์ข้อมูลกล้อง ใช้ `rain --start 2026-08-25 --end 2026-08-31` เพื่อระบุช่วงวันแทน ZIP ได้ การสร้างตารางกล้องดาวน์โหลด GeoJSON ของกรุงเทพฯ ประมาณ 62 MB หากดาวน์โหลดไว้แล้ว ใช้ `cameras --road-extract /path/to/Bangkok.osm.geojson.xz` เพื่ออ่านไฟล์นั้นซ้ำ ไฟล์ผลลัพธ์ใช้ UTF-8 BOM เพื่อให้ Excel อ่านภาษาไทยได้

## เชื่อมกับผลตรวจจับ

- **กล้อง** เชื่อมด้วย `camera_id` เก็บเป็นสตริงเพื่อรักษารหัสจากต้นทาง `road_name` กับ `alternate_road_name` คือถนนที่มีชื่อสองสายที่อยู่ใกล้พิกัดที่สุดในรัศมี 100 เมตร ถ้าระยะห่างจากกล้องต่างกันไม่เกิน 25 เมตร จะได้สถานะ `multiple_nearby_candidates` ใช้ภาพและคำบรรยายทิศทาง `direction` ประกอบเมื่อเลือกถนน โดยเฉพาะที่แยกและจุดที่ทางยกระดับซ้อนกับถนนพื้นราบ
- **ฝน** เชื่อมด้วย `camera_id` และ `hour_start` ตั้งเขตเวลาของเวลาในชื่อภาพเป็น `Asia/Bangkok` แล้วปัดลงเป็นต้นชั่วโมง เช่น `14:23` เชื่อมกับ `14:00+07:00` API รายงานฝนสะสมของชั่วโมงก่อนเวลาที่กำกับ สคริปต์จึงนำค่าที่กำกับ `15:00` มาเก็บในแถว `14:00` ค่าฝน `0` หมายถึงแหล่งข้อมูลรายงานว่าไม่ตก ส่วนค่าว่างหมายถึงไม่มีค่า ฝนเป็นค่าประมาณจากกริด ECMWF IFS ประมาณ 9 กม. กล้องหลายตัวใช้กริดเดียวกันได้
- **กฎ** ใช้ `scope_type`, `road_name`, `road_segment`, เวลา วันหยุดราชการ และ `vehicle_type` ร่วมกันหลังตรวจว่าภาพเป็นถนนช่วงที่ระบุ `source_type=government_summary` เป็นสรุปพื้นที่วงแหวนจาก สนข. รายละเอียดแนวถนนและการผ่อนผันอยู่ในรายงานที่ลิงก์ใน `supporting_source_url` หัวข้อ 2.3.1.13 หน้าพิมพ์ 2-49 ถึง 2-51 ส่วน `royal_gazette` เป็นกฎเฉพาะทางพิเศษที่ระบุในประกาศ ตารางนี้ยังขาดขอบเขตเชิงพิกัดและข้อยกเว้นระดับช่วงถนนสำหรับพื้นที่วงแหวน การใช้ตัดสินเหตุรายภาพจึงต้องตรวจช่วงถนนและข้อยกเว้นกับต้นฉบับก่อน

## วิธีเก็บข้อมูลสำหรับอธิบายในวิดีโอ

1. ส่งพิกัดกล้องและช่วงวันไปที่ Open-Meteo API เป็นชุด ตรวจจุดกริด เขตเวลา หน่วย และชั่วโมงที่ได้รับก่อนเขียน CSV
2. ดาวน์โหลดข้อมูลถนน OpenStreetMap ของกรุงเทพฯ แล้ววัดระยะจากพิกัดกล้องไปยังเส้นถนนที่มีชื่อ เก็บสองชื่อที่ใกล้ที่สุดพร้อมระยะ
3. ดาวน์โหลด PDF จาก สนข. แล้วใช้ `pypdf` ดึงช่วงเวลาและวันที่เริ่มใช้สำหรับพื้นที่วงแหวน ส่วน PDF ราชกิจจานุเบกษาใช้ฟอนต์ที่แปลงเนื้อหาไทยกลับเป็นข้อความได้ไม่ครบ จึงบันทึกเงื่อนไขข้อ 4–6 จากการตรวจหน้าต้นฉบับ แล้วให้สคริปต์ตรวจ SHA-256 ของไฟล์ก่อนสร้างตารางจากฉบับที่ตรวจแล้ว
